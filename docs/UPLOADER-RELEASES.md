# Portal installer releases

Practice setup: open Uploaders > Add uploader, download the current Windows ZIP, then continue to configure the uploader and generate its one-time code. No enrollment is created by requesting the download. The code expires 15 minutes after generation and is never bundled in the package. Extract all files, run the setup executable as administrator and select the empty non-patient pilot folder. Existing practice administrators and MSP administrators may download; viewers, editors, upload-only tokens and unrelated practices cannot authorize installer downloads.

A standalone Download current installer button is available for reinstall preparation without creating a device. The package remains an unsigned Windows x64 pilot with its Python runtime bundled. Publishing a release does not silently modify software already installed on practice computers. In-place upgrades, Authenticode signing and automatic updates require a separate release/update mechanism.

Distribution uses a separate private AES256 software bucket in the approved US-West account. It is separate from practice files, recovery backups and protected audit archives. The application stores only an encrypted single-bucket read credential in security_state, alongside verified release metadata. It issues 60-second single-object download links after normal authentication, MFA, role and CSRF checks. No new Vercel environment variables are required. Release metadata and its encrypted credential are covered by existing metadata backups; actual installer files remain in the software bucket. Normal provider storage/download charges apply to distribution traffic.

The operator publication tool requires an authenticated local storage CLI, approved account fingerprint, canonical HTTPS origin, an explicit version and --confirm-publish. It uploads to a content-addressed version path, downloads the stored bytes and checks SHA-256, validates a read-only credential, then updates the active release and appends an audit event. Temporary publishing credentials are restricted to this bucket, expire within one hour, and are revoked after publication. Previous release metadata and objects are retained; client retention and audit Object Lock are untouched. Do not overwrite a version with different bytes.

For future releases, increment VERSION in agent/vault_agent.py and run tools/build-pilot-installer.ps1 with -Publish, -ExpectedAccountFingerprint and -B2Cli. The build uses protected .env.runtime-production and .env.storage-secrets locally; neither file is bundled. The default build without -Publish produces local artifacts only. The same publication can be run separately with tools/publish-uploader-release.mjs --file <zip> --version <version> --origin <portal> --expected-account-fingerprint <approved hash> --b2-cli <CLI path> --confirm-publish, with those protected env files loaded. Build/publish is an operator release action, not a client setup task.
