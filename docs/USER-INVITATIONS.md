# Practice-user invitations

Only MSP administrators send enrollment or sign-in emails. First create/select the practice, open Users & access, add the exact email and role, then choose Send invitation. Saving a membership alone sends no email. Existing Clerk accounts receive generic Resend sign-in instructions; new accounts receive Clerk enrollment invitations valid for seven days. Account ready means the identity is known; it does not attest that MFA was completed in the current session.

The Clerk hosted Account Portal handles enrollment. Its configured Home/after-sign-up URL must return to https://www.streamlinedvault.com/. Configure required MFA and invite-only access mode in Clerk. Application membership remains authoritative: a Clerk account or invitation alone grants no practice role. Returning user remains sign-in only and the public New user button continues to open the request form. No new server secrets are required.

POST /api/tenants/:tenant/members/invitation accepts an assigned email and requires MSP membership, fresh MFA, origin and CSRF protection. One send per email per minute and 20 sends per administrator per hour are enforced in the shared database. The member response includes safe status, attempt timestamp and retry-after milliseconds. No invitation URL or token is stored or returned. Provider acceptance is distinct from inbox delivery. Failure is visible; manual retry is available after cooldown. Invitations are application-wide for an email, while roles remain practice-specific.

Removing the final practice membership revokes pending enrollment invitations. A provider outage never prevents local membership removal: revocation is marked pending and retried by security maintenance. Older links are revoked when resending. Remote acceptance and database commits cannot be atomic: on an ambiguous provider/network failure, the dashboard reports send failure rather than claiming delivery; an operator may need to reconcile invitations in Clerk before resending.

Migration 006 adds member_invitations and grants the existing restricted runtime role access to that table only. Recovery bundles include invitation history; restore clears provider IDs and marks invitation records revoked. Older bundles without the table remain supported. Restored environments remain blocked until isolated recovery review passes; restoring history does not revoke external provider links.
